# Java 개발 지침

- 코드를 바꾸기 전에 기존 패키지 구조, 네이밍, 예외 처리, 로깅 방식을 먼저 확인하고 그대로 따른다.
- 빌드 도구는 프로젝트에 이미 있는 것(Maven `pom.xml` 또는 Gradle `build.gradle*`)을 쓴다. 바꾸지 않는다.
- 새 의존성은 꼭 필요할 때만 추가하고, 이미 쓰는 라이브러리 버전과 호환되는지 확인한다. 추가했다면 이유를 기록한다.
- 변경한 동작에는 테스트(JUnit 등 프로젝트가 쓰는 프레임워크)를 함께 추가하거나 수정한다.
- 공개 API(컨트롤러, DTO, 인터페이스)를 바꿀 때는 호출하는 쪽을 모두 찾아 함께 고친다.
- 설정값과 비밀 정보(비밀번호, 키)는 코드에 직접 쓰지 않는다.
- 스택 버전과 최신 기법은 이 프로필의 `docs/` 폴더 문서에 정리된 내용을 우선한다. 문서에 없는 최신 기능은 확실하지 않으면 쓰지 말고 열린 질문으로 남긴다.
