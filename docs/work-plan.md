# OpenCode CLI 커스터마이징 작업 계획서 (최종안 v1.0)

> 작성 기준: 업스트림 `sst/opencode` 소스(커밋 `ecc4916`, 2026-10-06) 열람 + 사용자와의 요구 논의.
> 표기: `[검증]` = 소스에서 확인함, `[가정]` = 확인 전, `[기본값]` = 사용자 미확정이라 제안값으로 둠.
> 이 문서에는 코드를 넣지 않았다. 구현은 5장의 단계 순서대로 진행한다.
>
> **구현 현황 (2026-10-07)**: 이 계획은 `manager/`(ocx)에 구현되었다. 진행 상황은 `docs/dev-checklist.md`, 소스 검증·개발 중 발견한 사항은 `docs/phase0-findings.md`, 사용법은 `docs/user-guide.md`를 보라.
> 계획과 달라진 점: ① 기능 4(다중 모델 전환)는 범위에서 제외(모델 3개를 등록하고 실행 시 하나를 선택) ② Git은 자동 작업을 하지 않음 ③ 계획 모드의 질문은 원본 질문 도구가 비대화형에서 막혀 있어 ocx가 터미널에서 직접 함 ④ 낮 모드 감지는 이벤트가 아니라 로컬 측정 프록시로 토큰 단위로 함 ⑤ 모델 목록 스냅샷은 빈 JSON을 내장해 빌드 때 외부 접속이 필요 없음.
> 미검증: Windows 10/11 실제 실행(Linux에서 개발·검증, Windows exe는 빌드까지만 확인), 사내 Qwen 서버와의 실제 동작.

## 1. 목적과 배경

**목적**: OpenCode CLI를 폐쇄망 + 사내 로컬 LLM 환경에 맞게 쓰도록 구성하고, 두 가지 약점을 보완한 Windows 10/11용 exe를 만든다.

| 약점 | 현상 |
|---|---|
| 낮 시간 혼잡 | 사용자가 몰리면(특히 14~15시경) 제한된 GPU 때문에 평소 2~3분 작업이 20~30분 넘게 걸리고 완성도도 떨어진다. 지금은 사용자가 직접 중단하고 재시작한다. |
| 야간 무인 운영 | 퇴근 후 작업을 걸어 두고 아침에 완성된 결과를 받고 싶은데, 작업이 중간에 끊기거나 멈춘다. |

**전제 관찰**: 원본 OpenCode + Qwen 3.8 27B는 서버가 한가할 때 이미 잘 동작한다(사용자 경험). 새벽~07시에 모델 속도가 가장 좋다. 따라서 **원본을 유지하고 필요한 부분만 보강**한다.

| 구분 | 내용 |

| 대상 | OpenCode **CLI만** (데스크톱·웹·IDE 확장 제외) |

| 종료 시각 | 야간 모드 기본 **다음 날 07:00** |

## 3. 핵심 설계 원칙

1. **원본 유지, 개조 최소화**: OpenCode 소스는 가능한 한 수정하지 않는다. 업스트림 업데이트를 따라가기 쉽게 한다.
2. **원본을 감싸는 관리 프로그램**: 모드 선택, 감시, 재시작, 검증, 종료 판단, 리포트를 별도 프로그램이 맡는다. OpenCode exe와 함께 배포한다.
3. **계획 우선**: 항상 계획서를 먼저 만들고 승인받은 뒤 실행한다.
4. **의도 유지**: 사용자의 의도·범위·비목표가 실행 중에도 유지되도록 장치를 둔다.
5. **완료는 검증으로 판정**: 모델의 "끝났다"를 믿지 않고 빌드·테스트·체크리스트로 판정한다.
6. **안전 규칙은 모드와 무관하게 고정**: 허용/금지 명령, 작업 범위, Git 금지는 모든 모드에서 동일하다.
7. **측정 후 조정**: 응답 속도를 기록하고, 그 데이터로 낮/밤/오토 판단 기준을 조정한다.

## 4. 소스 검증 결과와 활용 방침

### 4.1 확인된 사실 `[검증]`

| 항목 | 확인 내용 | 활용 방침 |
|---|---|---|
| 빌드 | `packages/opencode/script/build.ts`가 Bun `compile`로 단일 exe 생성. 타깃에 `win32-x64`, `win32-x64-baseline` 포함. 패키지 매니저 `bun@1.3.14` | 기존 스크립트를 Windows x64로 한정해 사용 |
| 빌드 시 외부 접속 | 빌드 때 모델 목록 데이터를 가져와 exe에 내장 | 폐쇄망 빌드 환경에서는 사전 확보 |
| 설정 | `opencode.jsonc`/`opencode.json`/`config.json`을 전역·프로젝트에서 읽음. `OPENCODE_DISABLE_PROJECT_CONFIG` 존재 | JSON 설정 요구 충족 |
| 로컬 LLM 연결 | `@ai-sdk/openai-compatible` 내장 | 설정만으로 연결 |
| 부수 모델 | 설정 `small_model`로 제목 생성 등 보조 호출 모델 지정 | 보조 호출이 본 작업과 경쟁하지 않도록 조정 |
| 비대화형 실행 | `opencode run`: `--model`, `--agent`, `--session`, `--continue`, `--format`, `--file` 지원. 권한 요청은 승인 옵션이 없으면 자동 거부(멈추지 않음) | 관리 프로그램이 이 명령을 감싸 실행 |
| 내장 재시도 | `session/retry.ts`: 2초 시작, 2배 백오프, 최대 30초, **최대 5회** | 5회 초과 시 세션이 실패 → 장기 재시도는 관리 프로그램이 담당 |
| 에이전트 | `build`, `plan`(수정 도구 차단), `general`, `explore` 내장. 설정으로 커스텀 에이전트 추가(프롬프트, 모델, 단계 수, 권한) | 계획 작성 에이전트 정의에 활용 |
| 지침 파일 | `AGENTS.md`(전역·프로젝트) 로드 | 프로필의 스택 지침에 활용 |
| 스킬 | `SKILL.md` 기반, 외부 목록 조회 기능 있음 | 로컬 파일만 쓰도록 외부 스킬 차단 |
| 질문 도구 | 플래그(`OPENCODE_ENABLE_QUESTION_TOOL`)로 활성화 | 계획 모드의 대화형 질문 후보 |
| 외부 호출 차단 | `OPENCODE_DISABLE_MODELS_FETCH`, `OPENCODE_DISABLE_AUTOUPDATE`(설정 `autoupdate:false`), `OPENCODE_DISABLE_SHARE`, `OPENCODE_DISABLE_LSP_DOWNLOAD`, `OPENCODE_DISABLE_EXTERNAL_SKILLS`, `OPENCODE_PURE` | 환경변수와 설정으로 차단 |
| 모델 목록 | 런타임에 외부에서 가져오며 `OPENCODE_MODELS_URL`/`OPENCODE_MODELS_PATH`로 대체 가능 | 폐쇄망에서는 비활성화 또는 로컬 파일 지정 |
| 명령줄 | `yargs` 기반. 명령마다 설명을 가지며 `--help`가 자동 생성 | 우리 명령을 추가하면 도움말에 자연스럽게 포함 |
| Windows | `OPENCODE_DISABLE_FFF`가 Windows에서 기본 true | 실기 검증 필요 |

### 4.2 확인 전 `[가정]`
- 관리 프로그램이 `run`의 출력 이벤트(`--format`)에서 진행 상태를 읽을 수 있는지
- 중단한 세션을 `--continue`/`--session`으로 이어서 재개하는 동작
- 에이전트별 모델 지정과 설정 키의 정확한 이름
- 플러그인·MCP·프로바이더 플러그인의 런타임 외부 접속 전수 조사
- bash 도구 기본 타임아웃(`OPENCODE_EXPERIMENTAL_BASH_DEFAULT_TIMEOUT_MS`)이 Java 빌드에 충분한지
- 클라이언트 연결을 끊었을 때 서버가 요청을 취소하는지(재시작 시 서버 큐 영향)
- 사내 vLLM의 도구 호출 설정 상태(확인 수단 없음 → 실측으로 판단)
- Windows 10 최소 빌드, 사내 PC의 AVX2 지원 여부

## 5. 전체 구조

### 5.1 구성

| 층 | 구성 | 소스 수정 |
|---|---|---|
| OpenCode 원본 | CLI 본체(`run`, TUI 등) | 없음(원칙) |
| 설정·지침 층 | `opencode.jsonc`, 모델 3종 등록, 에이전트 정의, `AGENTS.md`, 스킬, 프로필 | 없음(설정과 파일) |
| 관리 프로그램 | 모드 명령, 참조 분석, 계획 단계, 감시·재시작, 검증, 종료 판단, 리포트, 도움말 | 신규 개발 |

### 5.2 모드 4종

| 모드 | 용도 | 사람 개입 |
|---|---|---|
| `plan` (계획) | 참조 자료 분석 → 계획서 2종 작성 → 승인까지. **코드는 수정하지 않음** | 있음 |
| `day` (낮) | 승인된 계획대로 진행하되 혼잡에 적응 | 보통 있음 |
| `night` (밤) | 승인된 계획대로 무정지 진행, 완료되면 자동 종료, 07:00 종료 | 없음 |
| `auto` (오토) | 시각·응답 속도·사람 유무로 낮/밤 동작을 자동 선택 | 상황에 따라 |

공통 옵션: 모델 선택(JSON에 등록된 3개 중 1개), 프로필, 계획서 경로, 작업 폴더.
명령 형태 `[기본값]`: 모드별 최상위 명령(`opencode plan`, `day`, `night`, `auto`). 원본 `opencode`/`opencode run`은 그대로 유지.

## 6. 기능 상세

### F1. 계획 우선 흐름과 계획 모드

1. **참조 자료 분석(F2)**
2. **의도·시나리오 계획서(MD)**: 무엇을, 왜, 범위, **비목표**, 사용할 참조 자료, 전체 완료 기준
3. **코드 작업 계획서(MD)**: 작업 목록, 작업별 대상 파일, 순서·의존, 검증 명령, 작업별 완료 기준, 작업 유형(구현/분석/MCP)
4. **사용자 승인**: 두 계획서를 확인. 계획 모드에서 모델이 모호한 부분을 **질문**하는 대화형을 기본으로 한다 `[기본값]`
5. **실행**: 낮/밤/오토

계획 작성 에이전트는 코드 수정을 못 하도록 권한을 제한한다(내장 `plan`과 유사). 사용자는 몇 줄의 지시만 쓰고, 모델이 계획서를 만든다. **완료 기준이 없는 작업은 "검토 필요"로 표시**한다.

**의도 유지 장치**
- 작업 시작마다 의도 계획서의 목적·비목표를 다시 주입
- 작업 종료 시 의도 계획서의 완료 기준과 대조 점검
- 계획서에 없는 파일 수정 시 경고 또는 차단(범위 제한)
- 계획 이탈 변경은 리포트에 별도 표시

### F2. 참조 자료 분석

- 사용자가 프로젝트의 지정 폴더에 참조 코드·문서를 넣는다(폴더 이름 `[기본값]` `reference/`).
- 양이 많아도 컨텍스트가 넘치지 않게 **모듈 단위로 나눠 분석**하고, 결과를 **노트 + 색인**으로 파일에 쌓는다.
- 대상 목록은 모델이 아니라 **스크립트로 추출**해 누락을 막는다.
- 이후 단계에서는 전체 노트가 아니라 **색인과 관련 노트만** 참조한다.
- 참조 폴더가 바뀐 경우에만 재분석한다. 진행 표시를 남겨 끊겨도 이어서 한다.
- 분석 문서(MD)의 검증: 대상 모듈 **커버리지**, 언급된 파일·클래스·함수의 **실제 존재 확인**, 문서 **형식** 준수. 내용 정확성은 자동 보장이 불가하므로 아침 리포트에 "검증됨/미검증"을 구분해 표시한다.

### F3. 낮 모드 (혼잡 적응)

목표: 사용자가 수동으로 하던 "느리면 중단하고 재시작"을 자동화한다. 서버를 못 바꾸므로 **속도를 올리는 기능이 아니라 낭비를 줄이고 멈추지 않게 하는 기능**이다.

1. **측정**: 호출별 첫 응답 시간, 초당 토큰, 작업 경과 시간을 기록(F7)
2. **감지**: 시간 예산 초과(평소 소요 시간의 배수), 진행 정체(마지막 출력 이후 경과), 같은 도구 호출·오류 반복
3. **단계적 대응**
   - 1단계: 같은 세션으로 이어서 재요청
   - 2단계: **새 세션 + 진행 상태 요약**만 전달해 입력을 가볍게 함
   - 3단계: 작업을 더 작게 나누거나 사용자에게 알리고 보류
4. **가볍게 만들기**: 가능하면 사고(thinking) 모드 끄기, 컨텍스트가 커지면 새 세션으로 이관, 불필요한 도구 끄기, 출력 상한, 보조 호출(`small_model`) 분리
5. **상태 이어받기**: 재시작해도 이미 한 일을 반복하지 않도록 진행 상태를 기록(수정 파일 목록과 변경 내용은 파일 백업과 비교해 파악)

수동 재시작이 효과 있는 이유(컨텍스트 길이 / 모델의 장황한 사고·반복 / 서버 요청 정체)는 아직 불명이므로, F7의 측정 기록으로 확인한 뒤 감지 규칙을 조정한다.

### F4. 밤 모드 (무정지 완주)

시작 전: 승인된 계획서 필수. 종료 시각 `[기본값]` 07:00.

**실행 루프(작업 단위)**
1. 새 세션으로 구현
2. 자동 검증(빌드·테스트)
3. 실패 시 오류를 전달해 수정 반복
4. **자체 점검 패스**: 검증 통과 후에도 별도 호출로 계획서 체크리스트와 대조해 빠진 부분 보완
5. 검증과 점검을 모두 통과해야 "완료"
6. 반복 실패·반복 루프는 **보류하고 다음 작업으로** 진행

**끊김 방지**
- 서버 오류·느림은 간격을 늘려 장기 재시도(내장 5회 한도를 넘어 시간 예산 내에서 계속)
- 진행 상태를 디스크에 계속 저장, 프로그램·PC 재시작 시 중단 지점부터 재개
- 작업마다 새 세션(컨텍스트 폭주 방지), 이전 내용은 요약만 전달
- 작업 유형별 시간 한도(Java 빌드 등은 크게)

**종료 조건**
- 정상: 모든 작업이 완료 기준(검증 통과 + 체크리스트 충족)을 만족
- 시간: 07:00 도달
- 정체: 남은 작업이 모두 보류
- 어느 경우든 **아침 리포트** 작성(F7)

**빠른 시간대 활용(옵션, 기본 꺼짐 `[기본값]`)**: 측정한 속도를 보고 초저녁~밤에는 작은·검증 쉬운 작업을, 새벽~07시에는 어렵고 큰 작업과 마지막 전체 점검을 배치한다. "새벽이 가장 빠르다"는 가정은 속도 기록으로 며칠 확인한 뒤 확정한다.

**실패 시 복구**: Git을 쓰지 않으므로 작업 전 대상 파일을 백업 폴더에 복사하고, 보류 처리할 때 복원한다.

### F5. 오토 모드

- **입력 신호**: 현재 시각, 최근 응답 속도(측정값), 사람이 화면에 붙어 있는지(대화형/무인)
- **판단 예시**: 빠르고 무인 → 밤 동작 / 느림 → 낮 동작 / 빠르고 사람 있음 → 일반 대화형
- 모드가 오락가락하지 않도록 **완충 구간**을 둔다
- 전환 시 **이유를 기록하고 화면에 표시**
- 안전 규칙은 모드와 무관하게 동일, **무인 시작에는 승인된 계획서 필수**(오토도 예외 없음)
- 기본은 보수적(애매하면 낮 동작)이며 속도 기록이 쌓이면 기준을 조정 `[기본값]`

### F6. 프로필 (Java / Python / AI / 분석)

실행 시 프로필을 선택하면 해당 묶음만 불러와 컨텍스트 낭비를 막는다.

| 프로필 구성 | 내용 |
|---|---|
| 스택 지침 | 사용 언어·프레임워크 버전, 권장 기법 (`AGENTS.md`로 제공) |
| 코딩 규약 | 사내 규약, 금지 패턴 |
| 검증 명령 | 빌드·린트·테스트 (Maven/Gradle, pytest 등) |
| 계획서 규칙 | 작업 쪼개기 방식, 완료 기준 필수 항목 |
| 참고 문서 | 사용자가 정리해 넣는 최신 API·기법 요약 |

- OpenCode는 범용 에이전트라 언어·스택별 최신 지침이 내장돼 있지 않다 `[검증]`. 모델의 학습 지식에는 한계가 있고 폐쇄망이라 최신 정보를 조회할 수 없으므로, **최신 정보는 사용자가 문서로 보충**한다.
- 작업 유형별 규칙: **구현형**(빌드+테스트 통과), **분석형**(F2의 분석 검증), **MCP 서버 개발형**(서버 기동 + 도구별 호출 테스트, 서버 프로세스와 포트 정리 절차 포함)
- 작업 유형별로 허용 도구를 제한한다(예: 분석형은 읽기 중심). MCP 도구가 많으면 도구 설명이 매 요청에 포함돼 컨텍스트와 GPU 부하가 늘기 때문이다.

### F7. 속도 측정·기록과 아침 리포트

- **측정 기록**: 호출별 첫 응답 시간, 초당 토큰, 작업 소요 시간, 재시도·재시작 횟수, 모드 전환 이유
- 용도: 낮 감지 규칙 조정, 오토 판단 기준 조정, 야간 효과 확인
- **아침 리포트**: 완료/보류/실패 작업, 작업별 변경 파일과 변경 내용(diff), 보류 사유와 마지막 오류, 검증됨/미검증 구분, 계획 이탈 변경, 소요 시간과 속도 요약

### F8. 폐쇄망 대응

| 항목 | 방법 |
|---|---|
| 모델 목록 조회 | `OPENCODE_DISABLE_MODELS_FETCH=1` 또는 `OPENCODE_MODELS_PATH` `[검증]` |
| 자동 업데이트 | `autoupdate:false` / `OPENCODE_DISABLE_AUTOUPDATE` `[검증]` |
| 공유 | `OPENCODE_DISABLE_SHARE` `[검증]` |
| LSP 다운로드 | `OPENCODE_DISABLE_LSP_DOWNLOAD` `[검증]` |
| 외부 스킬 | `OPENCODE_DISABLE_EXTERNAL_SKILLS` `[검증]` |
| 플러그인·MCP·프로바이더 플러그인 | 외부 접속 전수 조사 후 비활성화 `[가정]` |
| 웹 검색·웹 가져오기 도구 | 비활성화 `[가정]` |
| 프록시 환경변수 | 내부 주소 예외 처리 `[가정]` |
| 빌드 환경 | 모델 데이터·의존 패키지 사전 확보 |

HTTP 평문 통신(소스 코드 포함 전송)은 폐쇄망 한정 사용 전제를 문서화하고 보안 담당자 확인 항목으로 남긴다.
**검증**: 외부 네트워크를 차단한 상태로 실행하고 패킷 캡처로 외부 호출 0건 확인.

### F9. 도움말과 사용 가이드

- OpenCode 명령줄은 `yargs` 기반이라 우리 명령을 추가하면 `--help`에 자동 포함된다 `[검증]`
- **3층 구성**: ① 전체 개요(`--help`: 원본+우리 명령, "처음 쓰는 순서", 모드 비교표) ② 명령별 상세(옵션 표·기본값·예시·원본과의 관계·주의사항) ③ 사용 가이드 명령(시나리오별 사용법)
- **"하고 싶은 일 → 쓸 명령" 표**와 **항상 적용되는 규칙**(Git 금지, 허용/금지 명령, 작업 범위, 외부 호출 없음)을 도움말에 포함
- 설정 도움말: 현재 적용 설정과 파일 위치 출력, 항목별 설명과 예시, 한글 오류 메시지
- 도움말·메시지 언어 `[기본값]` 한글. 기본값은 코드의 실제 기본값에서 가져와 불일치를 막는다

### F10. 안전 규칙 (전 모드 공통)

- 허용: 빌드·테스트 등 사전에 정한 명령. 금지: 삭제·`git` 전반 등
- 작업 폴더 밖 수정 금지, 계획서 범위 밖 파일 수정 경고·차단
- 무인 실행 중 권한 요청은 사전 규칙으로 처리(승인 대기로 멈추거나, 무분별하게 전체 허용하지 않음)
- 작업 전 백업과 실패 시 복원
- PC 환경: 절전·화면 잠금·자동 업데이트 재부팅 방지, 재부팅 시 자동 재개(작업 스케줄러 연동)

## 7. 개발 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0. 기반 확인** | 원본 Bun 빌드, Windows x64(및 baseline) exe 생성, Windows 실기 실행. 모델 3종 등록·선택, 외부 호출 차단 설정, 도구 호출 실측(파일 읽기·수정·명령 실행) | 원본 exe가 폐쇄망 설정으로 Qwen 3.8과 정상 동작, `[가정]` 항목 판정 |
| **1. 측정 기반** | 속도 측정 기록(F7)을 먼저 구현, 며칠 수집 | 낮/밤 속도 차이와 느림의 원인 확인 |
| **2. 계획 모드** | 계획 작성 에이전트, 계획서 템플릿 2종, 참조 분석(F2), 프로필(F6) 기본 | 몇 줄 지시로 승인 가능한 계획서가 나옴 |
| **3. 낮 모드** | 감시·정체 감지·단계적 재시작·가볍게 만들기(F3) | 혼잡 시 사용자 수동 개입 없이 완주 |
| **4. 밤 모드** | 연속 실행·장기 재시도·재개·검증·자체 점검·종료 판단·리포트(F4) | 하룻밤 실증: 검증 통과 작업 완료, 막힌 작업은 보류, 07시 또는 완료 시 종료 |
| **5. 오토 모드** | 판단 규칙·완충·표시(F5) | 측정 기반 전환이 안정적으로 동작 |
| **6. 도움말·마무리** | 도움말 3층(F9), 패키징, (선택) 코드 서명·인스톨러 | 도움말만으로 처음 사용자가 계획→야간 실행까지 수행 |

단계 4 이후에도 원본 업스트림 동기화 절차(주기적 머지, 충돌 규칙)를 둔다. 각 단계 말미에 Windows 10/11 실기 검증을 포함한다.

## 11. 부록: 프로젝트 폴더 구성 (제안)

- `reference/` : 참조 코드·문서 (사용자 제공)
- `.plan/` : 의도 계획서, 코드 작업 계획서, 승인 기록
- `.notes/` : 참조 분석 노트와 색인
- `.batch/` : 진행 상태, 속도 기록, 백업, 아침 리포트
- 프로필 파일(스택 지침·규약·참고 문서)은 별도 `profiles/` 폴더에 프로필별로 보관

> 폴더 이름은 모두 제안값이며, 프로젝트 폴더를 오염시키지 않도록 한 곳에 모으는 방식도 검토한다.
